# 飞书空间瘦身 Skill

飞书空间满了，文档里又有不能丢的图片、视频、附件和子页面。这套 Skill 帮助 AI 在完整备份、逐项核验后整理空间，并检查替换文档造成的旧链接和分享权限变化。

它不靠降低视频画质来“压缩”。对于仍需在线协作的文档，使用原生副本保留当前内容；对于适合离线保存的素材库和历史项目，归档原始文件和索引。复制是否减少历史占用、何时释放空间，以平台实际核验为准，不保证固定节省比例。

## 能做什么

- 盘点大文档和素材库，区分在线保留与离线归档。
- 比对原件、副本的正文、样式、图片和附件内容。
- 检查批注、子页面、嵌入表格、画板和同步内容是否完整。
- 核对目标硬盘上的文件，生成可重新验证的 SHA-256 清单。
- 修复替换原件后的普通链接、文档卡片和页内锚点。
- 复查公开分享入口，区分互联网可查看、组织内可查看、可编辑及密码访问。
- 保存进度和原件到副本的映射，遇到缺失保留原件。

## 安装

在支持 Skill 的 AI 工具中安装仓库目录。以 Codex 为例，首次安装：

```sh
git clone https://github.com/huangbai-AI/feishu-space-cleanup.git ~/.codex/skills/feishu-space-cleanup
```

若目录已经存在，先检查现有内容，避免覆盖本地修改。重新加载工具或开启新会话后使用。

需要可用并已登录的 `lark-cli`；执行前由 AI 读取当前版本对应领域的使用指南。复杂网页操作可使用用户指定的已登录浏览器；本仓库不提供账号或授权信息。配套核验脚本只需 Python 3.10 及以上，无第三方运行依赖。

## 使用示例

> 用 `$feishu-space-cleanup` 盘点我指定范围内的大文档，先给出处理清单。

> 把这个素材库完整备份到我指定的移动硬盘，验证正文、记录与全部附件都能离线查看后，再按我确认的范围处理云端原件。

> 给这些脚本创建原生副本，确认素材、批注、子页面、分享权限和汇总页链接都保留，再删除已核验的旧原件。

Skill 不会把“整理一下”解释成清空回收站或公开私有文件。已明确批准的对象和操作可以继续执行；缺失内容或无法核验的文档保留原件。

## 本地核验工具

建立备份清单，再重新读取硬盘核验：

```sh
python3 scripts/backup_manifest.py create ./backup ./manifest.json
python3 scripts/backup_manifest.py verify ./backup ./manifest.json
```

清单可放在备份目录内或目录外，已有清单不会被覆盖。检查包括文件改动、丢失、新增、符号链接及越界路径；系统生成的 `.DS_Store` 和 `._*` 元数据不计入素材。

比较两份 `lark-cli docs +fetch --detail full` 的完整成功 JSON 响应：

```sh
python3 scripts/verify_copy.py source.json copy.json \
  --media-root ./backup --media-map ./media-map.json
```

`media-map.json` 的结构如下，键使用本次快照中的实际资源标识，路径相对于备份目录：

```json
{
  "SOURCE_MEDIA_ID": {"path": "original/attachment.mp4"},
  "COPY_MEDIA_ID": {"path": "copy/attachment.mp4"}
}
```

媒体从硬盘重新计算哈希，不信任清单里缓存的哈希。仅含文字的文档可省略媒体参数；有意改变标题时，可显式传入 `--allow-title-change`。

工具比较通过仅证明本次快照的正文和媒体一致，**不代表可以直接删除原件**。批注、特殊嵌入内容、未知标签及未展开引用会要求专项核验；目录、子页面、权限、反向链接和删除前版本稳定性也需另行验证。失败退出码为 `1`，输入或文件错误为 `2`。

```sh
python3 -m unittest discover -s tests -v
```
