# 复制与核验

## 操作依据

先读取当前环境的 `lark-doc` 读取、更新和素材下载参考；复制、删除、改名读取 `lark-drive`；知识库层级读取 `lark-wiki`。例如：

```sh
lark-cli whoami
lark-cli docs +fetch --doc "$SOURCE_URL" --detail full --as user
lark-cli drive +inspect --url "$SOURCE_URL" --as user
```

这些变量由用户当前任务的真实输入解析，不要沿用历史会话的标识。原生复制通常从 Drive 的复制能力或 Wiki 节点复制能力进入，具体参数以当前版本的指南为准。保持位置和层级；不要把 Wiki 节点标识当底层 Docx 标识。

## 验证内容

保存原件、副本及删除前最新快照，含完整 `content`、`reference_map`、版本信息和资源映射。

1. **正文与排版**：比较结构、顺序、文字、超链接、表格、图片位置、尺寸等。节点标识变化是正常的；任何额外差异都说明原因，不能为通过核验而盲目忽略属性或正文。
2. **素材**：原件和副本对应素材均下载原文件；重新从硬盘读取并逐项比较大小和 SHA-256。核对数量和实际内容，不能只比较名称、资源标识或文件存在。失效资源标识、空文件、下载失败、只有缩略图都阻塞删除。
3. **批注**：默认读取可能只返回未解决批注或被截断；需通过分页评论接口补全全部评论、回复、已解决状态、引用内容、作者、时间和附件。没有批注与未读到批注是不同结论。原生副本不保留时，按用户授权保存批注存档并验证，不声称评论线程完整迁移。
4. **特殊内容**：嵌入表格、Base、画板、同步块、文件卡片等按 archive.md 专项核验。当前通用脚本遇到它们会阻塞。
5. **子页面**：递归列出并保存顺序、节点标识和父节点关系。复制父页不代表复制孩子；确认副本自身是否已含孩子，避免重复迁移。操作后核对新旧两侧，保留独有子页面。不要递归删除仍带未迁移孩子的节点。
6. **稳定性**：核验中原件被他人编辑、增加批注或调整子页面，重新从当前状态开始对应核验。副本有新编辑也不能被旧备份覆盖。
7. **可用性**：确认目录位置、标题、已有分享范围及关键入口链接已准备好替换；通过才在授权范围内删除准确原件。

保守策略：无法证明完整就保留原件，而不是自动补空白、删掉无法读取的部分，或把有缺失的复制称为成功。

## 本地比较工具

`verify_copy.py` 输入成功的完整 XML 读取响应，不支持 Markdown 或片段。工具仅忽略块标识及已单独提示需专项核验的批注引用标识；保留其他正文、样式和资源属性。标题单独比较，仅通过显式参数接受有意改名。

媒体清单为 JSON 对象，键为本次资源标识，值为相对于指定媒体根目录的 `path`。工具自己计算文件校验值，不信任缓存的哈希；清单不要提交公开仓库。

```sh
python3 scripts/verify_copy.py source.json copy.json \
  --media-root ./backup --media-map ./media-map.json
```

只有不存在素材时可省略媒体参数。有资源、特殊内容、未展开引用、未知标签或批注时，缺少相应证明均返回失败；通过只表示工具覆盖的正文与媒体比较通过，不证明位置、权限、外部引用、子页面及源文档在删除时仍稳定，不产生删除许可。
